# 0008 UIをデジタル庁デザインシステム（DADS）に準拠させ、Tailwind CSSを使う

## 状況

フロントエンド（Next.js、#11）でUIを作り始めるにあたり、色・文字・余白・コンポーネントなどのデザインと、アクセシビリティの基準を決める必要があった。

## 決定

- UIは、デジタル庁デザインシステムβ版（DADS）に準拠する。理由はアクセシビリティ。JIS X 8341-3:2016 / WCAG 2.2 を前提にした基準に乗れる。ルールは `.claude/rules/dads.md` に置き、UIのデザインの正とする
- スタイルは Tailwind CSS（v4）と、DADSの公式テーマプラグイン `@digital-go-jp/tailwind-theme-plugin` を使う。DADSの公式のテーマプラグインとReact版のコードスニペットが、Tailwind CSSを前提に作られているため
- DADSの公式Markdown一式は `docs/dads/` に置いて参照するが、リポジトリには入れない（`.gitignore`）

## 捨てた選択肢

- デザインシステムを使わず、色や余白を自分で決める: アクセシビリティの基準を自分で満たす必要がある
- Tailwind CSSを使わず、DADSの値をCSS変数で自分で定義する: 公式のテーマプラグインとコードスニペットを使えない
- Tailwind CSS v3: 新しく導入するので、現行のv4にする。テーマプラグインはv3とv4の両方に対応している
- `docs/dads/` をリポジトリに入れる: 約1.2万行あり、公開リポジトリに置く場合は出典の記載も必要になる。公式のzipから取得できるので入れない

## 結果

#11 で導入した。

- Tailwind CSS v4 ＋ `@digital-go-jp/tailwind-theme-plugin` 1.0.1（Figmaデザインデータ 2.3.0〜2.14.0 に対応）。`frontend/app/globals.css` で読み込む。Tailwindの処理は、create-next-app@16.4.2 の既定の構成（`@tailwindcss/turbopack`）をそのまま使う
- テーマプラグインのv4版には、公式スニペットが使う `desktop:` のブレークポイントの定義がない（v3版にだけ `48em` がある）。`globals.css` の `@theme` で同じ値を補った
- 公式のReact版スニペット（`design-system-example-components-react` v2.7.0）から、見出し・説明リスト・ノティフィケーションバナー・プログレスインジケーターを `frontend/components/dads/` にコピーした。出典を各ファイルの先頭に書き、MIT Licenseの全文を置いた。このリポジトリのlintに通すため、または使わない部分を除くために変えた箇所は、その箇所にコメントで理由を書いた
- フォントは Noto Sans JP を `next/font/google` でビルド時に取り込む
